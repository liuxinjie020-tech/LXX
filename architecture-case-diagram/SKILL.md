# 建筑案例图解生成

## 目标

把“建筑是什么样”转化为“建筑为什么这样设计”。始终围绕以下因果链组织内容：

`场地问题 → 设计策略 → 空间生成 → 建筑表达`

不要只罗列材料、造型或照片；必须说明形式背后的设计问题与策略。资料不足时标明“待核实”，不得编造项目事实。

## 输入与资料处理

接受以下任意组合：建筑名称、建筑师、地点、年份、项目链接、现场照片、平立剖图、用户已有草图或文字说明。

1. 先整理基本信息：项目、地点、建筑师、年份、类型。
2. 区分“资料明确事实”和“基于图像或平面做出的推断”。
3. 如果用户提供网页或要求核实项目事实，读取来源并优先引用原始项目资料；如果无法访问，继续使用现有资料并列出待核实项。
4. 如果用户提供图片，先观察场地、体量、流线、开口、结构和材料，再提出分析；不要把不可见内容写成确定事实。

## 核心分析流程

### 1. 提炼设计问题

至少回答：建筑面对什么场地、功能或使用问题？哪些限制促成了设计决策？设计策略如何回应这些问题？

使用“问题—策略—结果”表达，避免只有形式描述。

### 2. 提炼一句话主题

输出格式：`项目名称｜一句话设计逻辑`

主题应描述可迁移的设计方法，例如“利用高差创造连续校园空间”“以围合组织连接科研与交流”，避免空泛的“现代、简洁、有特色”。

### 3. 生成四张固定分析图

每张图都要包含：图名、核心问题、图形动作、必要标注、建议视角和一句结论。

1. **场地响应**：建筑如何回应基地？表达高差、河流、城市界面、校园轴线、原有建筑、朝向、入口或视线。
2. **空间组织**：空间如何被组织？表达体量拆分、庭院、功能分区、公共空间、主次流线和内外关系。
3. **空间体验**：人在里面如何活动？表达渗透、灰空间、架空、穿行、停留、视线、光影和连续体验。
4. **建筑形式**：策略如何形成建筑语言？表达体量、屋顶、结构、开口、材料、立面节奏和构造逻辑。

四张图必须形成递进关系，不能重复画同一个平面：从基地到组织，从组织到人的体验，最后到可见的建筑表达。

## 图版组织

默认采用竖向案例图版：顶部放置“图解建筑案例”、项目名称、建筑师、地点/年份；中部放一至两张建筑照片或参考图；下部使用 2×2 四张分析图；底部放设计总结、可迁移设计手法和适用场景。

若用户已有画布比例或排版要求，优先服从用户要求；否则保持留白清楚、信息层级明确、图文对应。

## 手绘图与图像生成要求

需要生成或重绘图片时，默认使用以下视觉约束：建筑手绘轴测图、平面图或剖面图；黑色细线稿；红色马克笔分析线；少量淡彩；建筑比例和构造关系尽量准确；文字标注简短且不遮挡关键图形。

不擅自改变用户已有方案、建筑轮廓、空间关系或信息内容。用户说“内容不变”时，只优化线条、清晰度、层次和版面。

按需要从 [图版布局规范](references/poster-layout.md)、[分析框架](references/analysis-framework.md) 和 [图像提示词](references/image-generation.md) 中读取细节。

## 标准交付结构

除非用户指定其他格式，按以下顺序交付：

1. 项目基本信息与资料可信度说明。
2. 一句话设计逻辑。
3. 四张图的内容方案：场地响应、空间组织、空间体验、建筑形式。
4. 图版布局与视觉规范。
5. 可直接用于图像生成或重绘的提示词。
6. 设计总结：用三至五条说明可迁移的方法。

如果用户只要求优化图片，则只处理图像优化，不重新分析或改写案例内容；如果用户只要求文字方案，则不要虚构已生成图片。
